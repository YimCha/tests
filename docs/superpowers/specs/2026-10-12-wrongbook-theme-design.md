# 设计文档：错题本详情增强 + 模拟考试入错题本 + 浅色模式

- 日期：2026-10-12
- 状态：已评审（用户于头脑风暴阶段确认三项设计决策，均取推荐方案）
- 来源：真实用户使用反馈，三条均已核实为真问题
- 影响范围：`src/template.html`、`src/_app_script.js`、`src/debug/_sim_test.js`；构建产物 `模拟考试工具.html` 由 `src/build_bank.py` 重建

## 背景与目标

题库工具（单文件离线 HTML）交付用户后收到三条反馈：

1. **希望增加浅色模式**。当前 `template.html` 只有一套深色主题（`--bg0:#05070e` 等），无任何主题切换代码。
2. **错题本详情只有选项字母（如 "ABD"），没有选项正文**。错题本展开详情由 `reviewPractice()` 渲染，仅含题干、答案字母、解析，不含选项内容，也不显示用户当时的错选。
3. **模拟考试答错的题不进错题本**。全代码中 `recordWrong()` 唯一调用点是刷题练习的 `lockPractice()`；`submitExam()` 交卷判分时不记录错题。

### 成功标准

- 工具有可用的浅色主题，用户可切换并记住选择。
- 错题本展开可见完整选项正文、正确项高亮、（新记录）当时错选项标红。
- 模拟考试交卷后，答错的题按刷题同口径进入对应岗位错题本。
- 回归测试四件套全绿：`_test_logic.js`、`_sim_test.js`、`_draw_test.js`、`_paper_test.js`。
- 不触碰题干/答案数据口径，不引入第三方依赖。

### 已确认的设计决策

| 决策点 | 结论 |
|---|---|
| 主题切换方式 | 手动切换 + 跟随系统：默认读 `prefers-color-scheme`，首页右上角按钮三态循环（跟随系统 → 浅色 → 深色），选择存 localStorage |
| 旧错题记录（无 `ua` 字段） | 兼容显示：只高亮正确答案，不显示「当时错选」，不做数据迁移或清空 |
| 模拟考试错题口径 | 与刷题完全一致：fails+1、streak 清零、拉回待复习；多场考试答错同一题自动累计 |

## 详细设计

### 1. 浅色模式

**CSS（template.html）**

- 保留现有 `:root` 深色变量为默认；新增 `[data-theme="light"]` 选择器，覆盖全部颜色变量（背景、卡片、文字、边框、强调色、透明度辅助色）。
- CSS 中少量写死的深色字面量（滚动条渐变、`.exam-topbar` / `.es-actions` 的背景渐变等，约 5 处）改写为引用变量，保证两套主题下都正确。
- 主题切换不重载页面，仅切换 `<html>` 的 `data-theme` 属性。

**切换逻辑（_app_script.js 单源）**

- 存储 key：`localStorage('exam_tool_theme_v1')`，取值 `'light' | 'dark' | 'auto'`（缺省 `'auto'`）。
- 应用规则：`auto` 时按 `window.matchMedia('(prefers-color-scheme: light)')` 决定 `data-theme`；`light`/`dark` 直接设置。
- 监听 `matchMedia` 的 change 事件，仅当当前处于 `auto` 态时跟随刷新。
- 入口按钮位于首页右上角（与「抽签」「生成试卷」入口同区域），循环切换三态并即时生效；按钮文案用日常说法（如「主题：跟随系统 / 浅色 / 深色」），不出现技术术语。

### 2. 错题本详情补完整选项

**数据结构（_app_script.js）**

- `recordWrong(pi, qi, ok, ua)` 增加 `ua` 参数；答错时写入记录：`{fails, streak, mastered, ua}`（`ua` 为用户所选字母数组，判断题为 `['对']` / `['错']`）。
- 答对（streak 累计）路径不覆盖 `ua`，保留最近一次错选。
- 旧记录无 `ua` 字段，展示层判空兼容，不做迁移。

**展示（reviewPractice 重写）**

- 布局对齐模拟考试回顾 `reviewDetail()` 的选项样式：完整列出「字母 + 选项正文」；正确项绿色高亮；存在 `ua` 时，错选项红色并打 ✕。
- `ua` 缺失（旧记录）：只高亮正确项，不显示错选标记。
- 答案行由纯字母改为带内容的答案摘要；判断题仍显示「对 / 错」。
- 注意：`reviewPractice` 同时被错题本列表行展开与练习回顾复用，本次改动两处同时受益，测试需覆盖两条路径。

**调用点**

- `lockPractice()`（刷题锁定）：传 `ua`。
- `submitExam()`（新增调用，见下）：传 `ua`。

### 3. 模拟考试答错入错题本

- `submitExam()` 的判分循环中，`judgeOK(q, ua)` 为否的题调用 `recordWrong(st.pos, qi, false, ua)`。
- 归属：考试卷按岗位抽题，`st.pos` 即错题记录岗位，无歧义。
- 到时自动交卷（`examTimerLoop` 调 `submitExam()`）走同一代码路径，天然覆盖。
- 中途退出（未交卷）不记录，与「未交卷不算成绩」的直觉一致。
- 记录后 `pSave()` 持久化（IndexedDB 主存 + localStorage 冗余备份，沿用现有机制）。

## 错误处理

- `localStorage('exam_tool_theme_v1')` 读到非法值时按 `'auto'` 处理。
- 错题记录中 `ua` 含失效字母（题库更新导致选项数变化）时，展示层只标注仍存在的错选项，不报错（题库题号校验已有 `qi < BANK.q.length` 兜底，选项级异常仅影响展示不影响功能）。
- `matchMedia` 不可用（极老内核）时按深色处理，不阻塞初始化。

## 测试计划

- `_sim_test.js` 新增用例：
  - 模拟考试交卷后，答错的题出现在对应岗位错题本且 `fails=1`；再错一次累计 `fails=2`。
  - 错题记录含 `ua`，且与考试作答一致；答对 streak 路径不覆盖 `ua`。
  - 旧格式记录（无 `ua`）渲染不报错，正确项正常高亮。
  - 主题三态循环：`auto → light → dark → auto`，`data-theme` 与 localStorage 值随之变化；`auto` 态下切换系统偏好跟随刷新。
- `_draw_test.js` / `_paper_test.js` / `_test_logic.js` 原样回归，零改动预期全绿。
- 全部通过后 `python src/build_bank.py` 重建 HTML，人工抽查首页主题按钮、一次完整模拟考试交卷、错题本展开展示。

## 明确不做（YAGNI）

- 不做多主题（仅浅色/深色两套）。
- 不做错题记录的数据迁移、导出或清理工具。
- 不改错题本的统计口径（待复习/已掌握/高频阈值）与组卷、抽签功能。
